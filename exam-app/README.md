# آزمون کیس‌محور «واژه‌بان» — سامانهٔ آزمون آنلاین

سامانهٔ تک‌آزمونی برای کارشناسان پشتیبانی مؤسسهٔ سرخ، ساخته‌شده دقیقاً بر پایهٔ
`exam-vazheban-case.md` (نسخهٔ ۲.۰): همان ۲۵ سوال در ۱۰ بخش، همان کلید پاسخ، همان روبریک،
همان بارم ۱۰۰ و همان شرط قبولی (۶۵ از ۱۰۰ + حداقل ۶ از ۱۰ در بخش محاسبه).

## نقش‌ها

| نقش | دسترسی |
|---|---|
| شرکت‌کننده (پشتیبان) | ورود با نام کاربری و رمز اختصاصی، دیدن کیس کنار سوال، پاسخ‌دهی، ارسال، دیدن کارنامه |
| مصحح | دیدن همهٔ تلاش‌های ارسال‌شده، تصحیح بخش‌های باز با روبریک، دانلود CSV نتایج |
| مدیر | پنل `/admin`: ساخت شرکت‌کننده، تغییر رمز، بازنشانی تلاش، دسترسی به پنل مصحح |
| مدیر | `/admin/live`: وضعیت زندهٔ آزمون — چه کسانی در حال آزمون‌اند، پیشرفت هر نفر، دستگاه (گوشی/تبلت/لپ‌تاپ)، تعداد تمام‌کرده/منقضی/نیمه‌کاره و لاگ ورودها و عملیات |

## اجرا

```bash
python3 manage.py create-users --participants 10 --prefix sup
# خروجی: username,password,role  (رمزها را به پشتیبان‌ها بدهید)

python3 app.py                  # سرور روی 127.0.0.1:8090
python3 manage.py list          # فهرست کاربران
python3 manage.py reset-password sup03
python3 manage.py export --out results.csv
```

فهرست رسمی پشتیبان‌ها (۵۷ نفر) از یک فایل TSV با ستون‌های `UserName` و `Password` ساخته می‌شود.
`--replace` همهٔ شرکت‌کننده‌های قبلی و پاسخ‌هایشان را پاک می‌کند و فهرست تازه را می‌سازد
(کاربران مدیر و مصحح دست‌نخورده می‌مانند):

```bash
python3 manage.py import-users --file ../exam-users.tsv --replace
```

مدت آزمون ۶۰ دقیقه است (`EXAM["duration_minutes"]` در `exam_data.py`) و همهٔ متن‌های
راهنما و صفحهٔ ورود از همان مقدار خوانده می‌شوند.

هیچ وابستگی خارجی لازم نیست؛ فقط پایتون ۳.۱۰ به بالا و SQLite.

## ساختار

- `exam_data.py` — متن کیس، ۲۵ سوال، کلیدها، روبریک‌ها، پاسخ‌های مرجع
- `grading.py` — موتور نمره‌دهی خودکار (A، B، تشخیص C، D، E)
- `app.py` — سرور HTTP، صفحات RTL، پنل کیس، تایمر سمت سرور، پنل مصحح، CSV
- `db.py` — SQLite
- `tests/` — تست واحد و تست HTTP انتها-به-انتها
- `deploy/` — سرویس systemd، کانفیگ nginx (پورت ۸۴۴۴)، اسکریپت دیپلوی

## نمره‌دهی

**خودکار (۵۱ نمره):** A (۲۴) · B (۶ با نمرهٔ جزئی ۳ برای سه‌از‌چهار) · تشخیص C (۶) · D (۵) · E (۱۰ با بازهٔ ۲٪)
**دستی با روبریک (۴۹ نمره):** تصحیح جملهٔ C (۶) · F (۱۶) · G (۱۰) · H (۵) · I (۶) · J (۶)

تا وقتی همهٔ سوال‌های دستی تصحیح نشده‌اند، نتیجهٔ قبولی «قطعی» اعلام نمی‌شود.

## رفتار آزمون

- **تایمر سمت سرور:** مهلت هنگام شروع در دیتابیس ذخیره می‌شود؛ بستن مرورگر یا قطع اتصال آن را متوقف نمی‌کند.
- **بازگشت به آزمون:** کاربر با همان حساب وارد می‌شود، پاسخ‌های ذخیره‌شده برمی‌گردند و تایمر از همان مهلت ادامه می‌یابد.
- **پایان زمان:** سرور (در هر درخواست و همچنین یک حلقهٔ پس‌زمینهٔ ۲۰ ثانیه‌ای) تلاش منقضی را خودکار ارسال، ذخیره و برای مصحح قابل‌مشاهده می‌کند؛ کاربر پیام «وقت آزمون تمام شد» و نتیجه را می‌بیند.
- **موبایل:** نوار بالا (زمان باقی‌مانده و دکمهٔ ارسال) چسبیده می‌ماند؛ ابتدا متن کیس و سپس سوال‌ها نمایش داده می‌شود.
- **ورود:** نام کاربری از فهرست بستهٔ قابل‌اسکرول انتخاب می‌شود و رمز دستی وارد می‌شود. هر کاربر فقط یک نشست فعال دارد؛ ورود از دستگاه دوم نشست قبلی را می‌بندد و ثبت می‌شود.

## سلامت آزمون (ضدتقلب)

| سازوکار | رفتار |
|---|---|
| گزارش سلامت هر نفر | کارت «گزارش سلامت آزمون» در صفحهٔ تصحیح: مدت، پاسخ‌داده‌شده، زمان صرف‌شده، خروج از صفحه، تلاش چسباندن/کپی، ورود از دستگاه دیگر، پاسخ‌های شتاب‌زده |
| زمان‌سنجی هر سوال | ستون `time_spent` برای هر پاسخ؛ پاسخ زیر ۲۰ ثانیه «شتاب‌زده» علامت می‌خورد |
| حداقل کاراکتر | پاسخ سوال‌های تشریحی (C، F، I) کمتر از ۳۰ کاراکتر پذیرفته نمی‌شود؛ ارسال دستی مسدود و ارسال خودکار پایان زمان مستثناست |
| کپی/پیست | `copy`, `cut`, `paste`, `drop` در صفحهٔ آزمون مسدود و به `/api/event` گزارش می‌شود |
| خروج از صفحه | `visibilitychange` و `blur` ثبت می‌شوند |
| اسکرین‌شات | تشخیص PrintScreen/میان‌بر مک و مسدودسازی `getDisplayMedia`؛ محدودیت مرورگری، تضمین کامل نیست |
| تشابه پاسخ‌ها | ژاکار روی n-گرام کاراکتری با یکسان‌سازی فارسی؛ بیش از ۷۰٪ متوسط، ۸۰٪ بالا، ۹۰٪ بحرانی. در پنل مصحح و CSV |
| عدم افشای کلید | کلید و پاسخ مرجع فقط در پنل مصحح دیده می‌شود؛ شرکت‌کننده فقط نمره و درصد بخش‌ها را می‌بیند |
| یک‌بار آزمون | پس از ارسال (دستی یا خودکار) تلاش دوم ممکن نیست |

## امکانات تکمیلی

- **وضعیت زنده (`/admin/live`):** هر ۲۰ ثانیه تازه می‌شود. آزمون‌دهنده‌ای که بیش از دو دقیقه هیچ درخواستی نفرستاده «نیمه‌کاره خارج‌شده» شمرده می‌شود (تایمرش در سرور ادامه دارد). دستگاه از User-Agent تشخیص داده می‌شود.
- **لاگ ورود و عملیات:** جدول `audit` شامل ورود، خروج، ورود ناموفق، شروع/ارسال آزمون، ارسال خودکار و اقدام‌های مدیر؛ فقط ۵۰۰۰ رخداد آخر نگه داشته می‌شود.
- **ذخیرهٔ آفلاین:** Service Worker (`/sw.js`) پوستهٔ برنامه (CSS/JS) را کش می‌کند و در قطعی اتصال صفحهٔ دوستانهٔ آفلاین نشان می‌دهد؛ پاسخ‌های ذخیره‌نشده در `localStorage` می‌مانند و با برگشت اینترنت خودکار دوباره ارسال می‌شوند. صفحه‌های آزمون و `/api/*` هرگز کش نمی‌شوند.
- **صفحهٔ خطای دوستانه:** ۴۰۴ و خطاهای غیرمنتظره (۵۰۰) با صفحهٔ فارسی روشن و دکمهٔ بازگشت نمایش داده می‌شوند.
- **پاسخ‌های نادرست در پنل مصحح:** کارت «پاسخ‌های نادرست» با فهرست کوتاه «غلط‌ها: A3، D2» و دلیل هر مورد (گزینهٔ اشتباه، کلید درست، گزینهٔ جاافتاده).
- **دسترس‌پذیری:** برچسب‌های `aria-label` روی دکمه‌ها و فیلدهای اصلی، ناحیهٔ `aria-live` برای شمارندهٔ کاراکتر و تعداد پاسخ‌ها، و `aria-expanded` روی دکمهٔ بستن کیس.
- **کارنامهٔ قابل دانلود:** `/report/<attempt_id>` برای صاحب تلاش و مصحح/مدیر؛ شامل نمرهٔ بخش‌ها، مباحث مسلط، مباحث نیازمند مطالعه، مباحثی که احتمالاً درک نشده، راهنمای مبحثی و برنامهٔ بهبود. با `?download=1` به‌صورت فایل HTML مستقل ذخیره می‌شود (قابل چاپ/PDF).

## تست

```bash
python3 -m unittest tests.test_exam -v
python3 tests/test_http.py -v
python3 tests/test_responsive.py -v
node tests/test_examjs.js          # اجرای واقعی exam.js در محیط DOM حداقلی
```

`tests/test_examjs.js` فایل `exam.js` را در یک DOM حداقلی واقعاً اجرا می‌کند؛
خطاهای زمان اجرا (مثل متغیر تعریف‌نشده) را که `node --check` نمی‌بیند می‌گیرد و
بررسی می‌کند تایمر مقدار زمان نشان بدهد، نه `--:--`.

`tests/test_responsive.py` بدون مرورگر، همهٔ صفحه‌ها را می‌گیرد و سه چیز را تضمین می‌کند:
هر جدول داخل قاب اسکرول خودش است، هیچ عنصری عرض ثابت بزرگ‌تر از صفحه ندارد، و
قواعد محافظ چیدمان (شبکه‌های کوچک‌شدنی، محافظ سرریز افقی، شکستن جدول تطبیق در موبایل)
سر جایشان هستند.

## رسپانسیو و پالت رنگ

- **پالت:** زغالی `#2e2a2a` برای سطوح تیره، قرمز `#c0413c` برای کنش، پس‌زمینهٔ سرد
  `#f5f7f8` و خاکستری `#61707f` برای متن کم‌رنگ. همهٔ جفت‌های متن/پس‌زمینه
  دست‌کم نسبت تضاد ۴.۵ (WCAG AA) دارند و `tests/test_responsive.py` همین را می‌سنجد.
- **حاشیهٔ کناری در موبایل:** ۲۰ تا ۲۴ پیکسل از هر طرف؛ قاعدهٔ قدیمی
  `body.auth main { padding: 0 }` پدینگ صفحهٔ ورود را صفر می‌کرد و حذف شده است.
  نوار تایمر چسبیده هم به‌جای چسبیدن به لبه، پدینگ کناری دارد.
- **بدون اسکرول افقی:** `body` محافظ `overflow-x: clip` دارد (برخلاف `hidden`، چسبندگی
  نوار بالای آزمون را خراب نمی‌کند) و همهٔ جدول‌ها داخل `.table-wrap` با اسکرول افقی
  مستقل می‌لغزند، نه کل صفحه.
- **نقاط شکست:** ۱۲۸۰ (فاصله‌های لپ‌تاپ باریک)، ۱۰۸۰ (ورود تک‌ستونه)، ۹۰۰ (آزمون موبایل)،
  ۸۲۰ (وضعیت زنده تک‌ستونه)، ۶۴۰، ۵۶۰ (جدول تطبیق کارتی)، ۴۰۰.
- **شبکه‌های کشسان:** ستون‌های صفحهٔ ورود و ستون کیس/سوال با `minmax(0, …)` می‌توانند
  کوچک شوند؛ هیچ ستون ثابتی صفحه را پهن نمی‌کند.
- **متن‌های بلند:** `overflow-wrap` روی سلول‌ها و پاسخ‌های تشریحی، تا یک واژهٔ طولانی
  (نام کاربری یا عدد) صفحه را پهن نکند.

### پشتیبان‌گیری از دیتابیس (ضروری)

`exam.db` تنها نسخهٔ پاسخ‌هاست. یک بار این cron را روی سرور نصب کنید؛ هر روز ۳ بامداد از `/var/backups/vazheban-exam` نسخه می‌گیرد و ۱۴ نسخهٔ آخر را نگه می‌دارد:

```bash
ssh root@46.34.163.254 'mkdir -p /var/backups/vazheban-exam && (crontab -l 2>/dev/null | grep -v backup-db.sh; echo "0 3 * * * /opt/vazheban-exam/deploy/backup-db.sh >> /var/log/vazheban-backup.log 2>&1") | crontab -'
ssh root@46.34.163.254 '/opt/vazheban-exam/deploy/backup-db.sh'
```

بازیابی: سرویس را متوقف کنید، فایل پشتیبان را روی `exam.db` برگردانید (`systemctl stop vazheban-exam` → `cp /var/backups/vazheban-exam/exam-XXXX.db /var/lib/vazheban-exam/exam.db` و حذف `exam.db-wal`/`exam.db-shm`) و سرویس را دوباره روشن کنید.
